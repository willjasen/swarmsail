# Swarmsail scripts

- `provisioning_worker.py` - Fixed node-local adapter supervised by the Rust private provisioner. It reconciles owned Headscale/Compose, externally installed wildcard DNS/TLS, ingress and policy, and authoritative enrollment/node metadata. It is not a public endpoint or a DNS provider client. See [default-tailnet provisioning](../runbooks/provision-default-tailnet.md).
- `adopt_default_tailnet.py` - Explicit preview/apply adoption of an owned isolated managed generation as the account default. It refuses reassignment and never deploys or marks ready.
- `provision_subscriber.py` — Reserve multiple independent managed Headscale tailnets for an opaque subscriber account after an operator has verified an active trial or subscription. Run `python3 -m scripts.provision_subscriber --help`. It reads an existing `instances.json`, previews by default, and requires `--apply` to write the config and local Swarmsail SQLite mappings. It does not deploy the instances or configure DNS/ingress.
- `issue_lan_certificate.sh` — Preview or issue/renew a trusted certificate for `headscale.example.test` through lego and Cloudflare DNS-01. Requires Docker and a mode-600 token at `~/Library/Application Support/Swarmsail/cloudflare-dns-token`; use `--apply` to change ACME/DNS state. It never prints the token.
- `verify_droplet_ipv4.py` — Verify that a droplet's configured public IPv4 matches DigitalOcean metadata and that configured service hostnames resolve directly to it. Run with `python3 -m scripts.verify_droplet_ipv4 --config <path>` from the repository root.

The existing root-level `manage_headscale.py` generates managed Compose and Headscale config files. When `caddy.enabled` is true, it generates a Caddy DNS-01 reverse proxy for each managed Headscale `server_url`; optional `caddy.proxy_routes` can route other approved services across explicitly declared `caddy.external_networks`. Set `health_upstream` on a proxy route to send only `/health` to a separate status page while keeping other paths on the primary upstream. When CrowdSec is enabled, the generated Caddy image includes the pinned CrowdSec HTTP bouncer, Caddy writes access logs to `caddy.log_dir`, and managed CrowdSec acquires those logs. Set `crowdsec.bouncer_api_key_path` to a node-local key file; Compose mounts it as a secret and the generated Caddyfile contains no key value. See the [Caddy ingress runbook](../runbooks/2026-10-18-swarmsail-caddy-headscale-ingress.md) for rollout and verification. The Cloudflare token also stays in a node-local read-only secret file. `python3 manage_headscale.py generate --config <path>` previews; add `--apply` only after reviewing the target. The Swarmsail web process also imports its config loader and generator.
